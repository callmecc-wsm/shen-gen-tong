## PM 摘要（What & Why）
- 问题：在总览页的步骤卡片中，左侧“序号圆角块”会在该步已有部分进展时变为蓝色，但右侧状态气泡并不显示“进行中”。这让用户误以为该步尚未开始。
- 原因：两套逻辑不一致。
  - 序号颜色依据“该步是否有部分完成”（inProgress）。
  - 状态气泡的“进行中”依据“全局第一个未完成的步骤”（当前步）而非该步骤自身进展。
- 目标：统一标准——只要该步存在部分完成（未达100%，已>0），序号蓝色与气泡“进行中”同时生效，避免认知冲突。

## 技术方案（How）
- 统一判定口径：使用 perStep 的 `inProgress`（总数>0 且已完成>0 且 pct<100）。
- 主要改动文件与位置：
  - `app/overview/OverviewClient.tsx`
    - 现状：
      - 序号颜色：第177行，基于 `perStep.find(x => x.id === step.id)?.inProgress`（正确）。
      - 完成判定：第165行 `const isCompleted = !!ps?.completed`（保持）。
      - “进行中”气泡：第191～192行，依赖 `isCurrent`，而 `isCurrent` 在第166行是通过“全局首个未完成步骤”计算（不一致）。
      - 箭头 hover 高亮：第178行也依赖 `isCurrent`。
    - 修改：
      - 用 `const isInProgress = !!perStep.find(x => x.id === step.id)?.inProgress;` 作为统一的“进行中”判定。
      - 将状态气泡的条件改为 `isInProgress`：第191～192行文本与样式从 `isCurrent` 切换为 `isInProgress`，非进行中显示“待开始”。
      - 箭头 hover 高亮也改为使用 `isInProgress`，确保视觉语义一致：第178行。
      - 保留 `isCompleted` 用于“已完成”分支，不改变完成态计算。
  - `components/OverviewChecklistDrawer.tsx`
    - 现状：第101～103行，`isDone` 与 `isCurrent` 实际已采用“该步是否部分完成”的语义（`!isDone && sp.completed > 0`），与目标一致。
    - 无需改动，保持与卡片一致性。

- 不改动文件：
  - `app/step/[id]/StepContent.tsx`：该文件的头部数字固定为蓝色以强调当前详情页步，仅用作页面视觉标识；不涉及总览卡片的状态气泡逻辑。

- 验证用例：
  1. 某步 `total=5, completed=0` → 序号灰色、气泡“待开始”。
  2. 某步 `total=5, completed=2` → 序号蓝色、气泡“进行中”。
  3. 某步 `total=5, completed=5` → 序号绿色、气泡“已完成”。
  4. 多步同时部分完成 → 每个相关卡片均显示蓝色+“进行中”。

  - 仅为条件渲染调整，逻辑可逆；若需回滚，恢复 `isCurrent` 的旧判定即可。
