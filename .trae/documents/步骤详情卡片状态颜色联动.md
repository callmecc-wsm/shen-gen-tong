## PM 摘要（What & Why）
- 目标：让步骤详情页顶部的“序号方块”和卡片右下角的“状态气泡”跟随步骤状态变化，以与总览页的体验一致。
- 规则：
  - 已完成：序号与气泡均为绿色。
  - 进行中：序号与气泡均为蓝色（风格参考“已完成”——实心浅底+明显边框），不再是白底仅悬停变蓝。
  - 待开始：卡片仍为灰色，序号与气泡为灰色。
- 价值：用户在详情页也能一眼确认当前步骤的状态，降低认知切换成本，与总览页视觉语言保持一致。

## 技术方案（How）

### 状态来源与判定
- 状态数据来源：沿用现有进度统计方法，优先使用云端同步 Hook。
  - `lib/useProgress.ts`：`getStepProgress(stepId)` 返回 `{ completed, total }`（云端实时数据）。
  - 备用：`lib/store.ts` 本地 `getStepProgress(stepId)`（若云端不可用时）。
- 判定规则（与总览页一致）：
  - 已完成：`total > 0 && completed === total`
  - 进行中：`!已完成 && completed > 0`
  - 待开始：`completed === 0` 或 `total === 0`

### 需要修改的文件
- `app/step/[id]/StepContent.tsx`
  - 序号方块位置：`app/step/[id]/StepContent.tsx:73`（当前固定 `bg-blue-600 text-white`）。
  - 标题卡片右侧按钮位置：`app/step/[id]/StepContent.tsx:83-90`（在此区域新增右下角状态气泡）。

### UI改动与样式映射
- 新增动态样式映射（Tailwind 类）：
  - 序号方块（方形徽章）：
    - 已完成：`bg-green-600 text-white shadow-green-200`
    - 进行中：`bg-blue-600 text-white shadow-blue-200`
    - 待开始：`bg-gray-300 text-gray-700 shadow-none`
  - 右下角状态气泡（pill）：
    - 已完成：`bg-green-100 border border-green-300 text-green-800`
    - 进行中：`bg-blue-100 border border-blue-300 text-blue-800`
    - 待开始：`bg-slate-100 border border-slate-200 text-slate-600`
- 交互与布局：
  - 在标题卡片容器内（`app/step/[id]/StepContent.tsx:71-91`）增加一个绝对定位的右下角 `span`，显示状态文案（“已完成/进行中/待开始”）并套用对应类。
  - 保持移动端与桌面端一致显示；不引入悬停依赖的颜色变化，确保触屏设备体验一致。

### 代码级实施步骤
1. 引入进度 Hook：`import { useProgress } from "@/lib/useProgress";`
2. 在组件内调用：
   - `const { getStepProgress } = useProgress();`
   - `const { completed, total } = getStepProgress(\`step${stepId}\`);`
   - 根据规则生成 `status` 与布尔值 `isDone/isCurrent/isIdle`。
3. 根据 `status` 动态拼接 Tailwind 类：
   - 序号方块：将原固定类替换为 `className={badgeClass}`，`badgeClass` 基于 `status` 选择上述颜色类。
   - 右下角气泡：在标题卡片内部新增 `span`，内容为状态文案，类为 `pillClass`，同样按 `status` 映射。
4. 与总览页口径对齐：
   - 总览页参考：`app/overview/OverviewClient.tsx:171-187` 的状态颜色。我们采用“已完成”同款视觉，但将“进行中”改为蓝色，避免白底仅悬停变蓝的不一致。

### 选项对比（CTO建议）
- 方案A（MVP/快速）：在 `StepContent.tsx` 中直接使用本地 `lib/store.ts` 的 `getStepProgress`。
  - 优点：零新依赖、实现最快。
  - 缺点：仅本地进度，若云端数据已更新则详情页可能不同步。
- 方案B（可扩展/推荐）：使用 `lib/useProgress.ts`（云端实时）作为主来源，缺失时回退到本地存储。
  - 优点：与待办侧拉窗（`TodoSidebar`）一致的实时状态；体验统一。
  - 缺点：稍多逻辑分支，但复杂度可控。
- 建议：选方案B，确保状态与云端一致。

### 验收标准
- 在总览页标记第2步为“进行中”时，进入详情页：
  - 序号方块为蓝色。
  - 右下角气泡文本为“进行中”，气泡为蓝色。
- 当勾选本步骤所有待办后：
  - 序号方块变为绿色。
  - 右下角气泡文本为“已完成”，气泡为绿色。
- 未勾选任何待办时：
  - 序号与气泡为灰色。
- 移动端与桌面端显示一致，无需悬停动作也能区分状态。

### 回滚与影响面
- 所有改动仅在 `StepContent.tsx`，无全局样式改写；如需回滚，恢复原固定颜色类即可。
- 不影响 `Sidebar`、`MobileMenu` 的当前步高亮逻辑。
