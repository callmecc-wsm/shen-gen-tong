## 一、项目概述

### 1.1 项目背景

申根签证申请流程复杂，涉及多达10多个文件、无数个细节要求，让许多计划前往欧洲旅行的用户感到困扰。

**当前用户面临的痛点：**

1. **信息分散**：需要在小红书、各类攻略网站、论坛中反复搜索，花费大量时间收集信息
2. **细节繁多**：每份材料的具体要求（如银行流水余额、保险购买页数、在职证明格式等）不统一
3. **容易出错**：材料准备稍有疏漏就可能导致拒签，造成时间和金钱损失
4. **选择困难**：
   - 找旅行社代办：费用高（上千元），服务质量参差不齐，可能存在坑（如中途取消酒店导致拒签）
   - DIY申请：最经济划算，但需要投入大量时间精力学习和准备

### 1.2 产品定位

**申根签证准备助手**是一个**交互式、一站式的签证准备引导平台**，专注于帮助用户：

- ✅ **高质量**：提供万无一失的材料准备指导，尽可能避免拒签风险
- ✅ **省心省力**：将分散的信息统一汇总，提供标准化的操作流程和模板
- ✅ **无脑跟随**：每个步骤都极度细致，用户只需按照指引操作即可完成

**核心价值主张：**
> "让用户既能享受DIY的经济实惠，又能获得接近专业服务的质量和省心体验"

### 1.3 目标用户画像

**主要用户群体：**

1. **首次申请申根签证的旅行者**
   - 对流程完全不熟悉
   - 希望有详细指导避免踩坑
   - 愿意为优质信息付费（20元左右）

2. **追求性价比的DIY爱好者**
   - 不想花上千元找旅行社
   - 有一定自主能力，但需要系统化指引
   - 重视材料质量，希望一次通过

3. **时间有限的职场人士**
   - 工作繁忙，无暇到处搜集信息
   - 需要清晰的checklist跟踪进度
   - 希望快速高效完成准备工作

**用户特征：**
- 年龄：25-45岁
- 地域：重庆、四川、贵州、云南（重庆领区）
- 收入：中等及以上（有能力支付欧洲旅行费用）
- 能力：具备基本的电脑/手机操作能力和文档处理能力

### 1.4 产品目标

**MVP阶段目标（第一版）：**

1. **覆盖意大利旅游签证（重庆领区）**的完整申请流程
2. 提供**10个核心步骤**的详细引导，每个步骤都有清晰的操作指南
3. 实现**交互式Checklist**功能，用户可以勾选完成状态并保存进度
4. 提供**必要的模板文件下载**和外部资源链接
5. 实现**激活码验证机制**，支持一次性激活码购买使用

**成功指标：**
- 用户完成率 > 80%（激活后至少完成80%的步骤）
- 用户平均准备时间 < 8小时（相比传统方式节省50%以上时间）
- 材料准备一次通过率 > 95%

**后续迭代方向：**
- 扩展到其他申根国家（法国、德国、西班牙等）
- 增加用户账号体系，支持多设备同步
- 提供在线咨询或AI智能问答功能
- 开发移动端APP

### 2.2 核心功能模块

#### 2.2.1 激活码验证模块

**功能描述：**
用户需要输入有效的激活码才能访问完整的签证准备内容。

**关键特性：**
- 一次性激活码机制（一个激活码只能使用一次）
- 激活后绑定到浏览器本地存储，无需重复输入
- 激活码格式：12位字符（如：VISA2025-ABC1）
- 支持激活码失效提示和错误处理

**交互流程：**
1. 用户访问网站，首先看到激活码输入页面
2. 输入激活码并点击"激活"
3. 系统验证激活码有效性：
   - ✅ 有效且未使用 → 标记为已使用，跳转到国家选择页
   - ❌ 无效 → 提示"激活码无效，请检查后重试"
   - ❌ 已使用 → 提示"该激活码已被使用"
4. 激活状态存储在localStorage，用户关闭浏览器后再次访问无需重新输入

**技术实现建议：**
- 激活码存储在配置文件中（JSON格式）
- 每个激活码有状态标识：`unused`（未使用）/ `used`（已使用）
- 激活后在localStorage存储标识：`activated: true`

#### 2.2.2 国家选择模块

**功能描述：**
展示申根国家列表，用户选择要申请签证的目标国家。

**当前状态（MVP）：**
- ✅ **意大利**：完全开放，可点击进入
- ⚪ **其他申根国家**（法国、德国、西班牙、希腊等）：置灰显示，鼠标悬停提示"该国家暂未开放，正在迭代中"

**页面设计：**
- 卡片式布局，每个国家一个卡片
- 卡片包含：国旗图标、国家名称、适用领区提示
- 意大利卡片：彩色显示，有明显的"开始准备"按钮
- 其他国家卡片：灰度显示，不可点击，带"即将上线"标签

**扩展性设计：**
- 未来添加新国家时，只需修改配置文件，无需改动代码结构
- 每个国家对应独立的内容文件夹，便于管理

**步骤页面结构（通用模板）：**

每个步骤页面包含以下标准化内容：

1. **步骤标题和编号**
2. **引导语**：用亲切的语气说明本步骤的目的和重要性
3. **核心内容**：详细的操作指南、要求说明
4. **交互式Checklist**：该步骤的待办事项列表
5. **常见错误提示**：用红色高亮显示容易出错的地方
6. **情绪缓解话术**：针对用户可能的焦虑点进行心理疏导
7. **模板和工具**：可下载的模板文件或工具链接
8. **导航按钮**：上一步 / 下一步 / 返回总览

#### 2.2.4 交互式Checklist模块

**功能描述：**
在每个步骤中，用户可以勾选已完成的待办事项，系统自动保存进度。

**关键特性：**
- ✅ 每个checklist项可以勾选/取消勾选
- 💾 勾选状态自动保存到浏览器localStorage
- 📊 总览页面显示整体完成进度（如：已完成 25/45 项，56%）
- 🔄 用户可随时返回任意步骤查看或修改状态

**交互设计：**
- 未完成：空心圆圈 ⚪
- 已完成：绿色对勾 ✅
- 点击切换状态，有动画效果
- 每个步骤的完成度显示：如"步骤4：材料清单 (8/12 项已完成)"

**数据存储方案：**
```json
{
  "step01": {
    "item01": true,
    "item02": false
  },
  "step02": {
    "item01": true,
    "item02": true,
    "item03": false
  }
  // ...
}
```

## 三、页面交互与用户体验

### 3.1 导航逻辑

**主导航结构：**
```
首页（激活码验证）
    └→ 国家选择页
        └→ 意大利签证准备 - 总览页
            ├→ 步骤01：领区确认
            ├→ 步骤02：主目的地判断
            ├→ 步骤03：时间规划与预约
            ├→ ...
            └→ 步骤10：审理与取证
```

**导航方式：**
1. **顶部导航栏**：显示当前进度和步骤编号
2. **侧边栏目录**：可快速跳转到任意步骤（仅在PC端显示）
3. **底部按钮**："上一步"、"下一步"、"返回总览"
4. **进度条**：顶部显示 1/10 → 2/10 → ... → 10/10

**跳转规则：**
- 用户可以自由跳转到任意步骤（不强制按顺序完成）
- 但建议按顺序完成，未完成的步骤会有提示标识
- 点击"返回总览"可查看所有步骤的完成情况

### 3.2 提示和警告的呈现方式

**信息层级设计：**

1. **🔴 严重错误/强制要求**
   - 红色背景高亮显示
   - 用于必须遵守的硬性规定
   - 示例："切勿提交假材料！任何伪造材料一经发现将直接拒签"

2. **⚠️ 重要提示/常见错误**
   - 黄色边框高亮
   - 用于容易踩坑的地方
   - 示例："护照有效期必须至少还有3个月，否则无法受理"

3. **💡 贴心提示/优化建议**
   - 蓝色背景，轻量提示
   - 用于增值建议和小技巧
   - 示例："建议提前1.5个月开始准备，时间更从容"

4. **💚 情绪缓解/鼓励话术**
   - 绿色文字，温暖语气
   - 用于缓解用户焦虑
   - 示例："不用紧张，我们已经帮你准备好了所有模板，跟着做就好！"

### 3.3 移动端适配策略

**响应式设计原则：**
- 采用移动优先设计（Mobile First）
- 断点设置：
  - 手机：< 768px
  - 平板：768px - 1024px
  - PC：> 1024px

**移动端特殊优化：**
1. **侧边栏改为底部导航**：步骤列表改为底部抽屉式菜单
2. **字体大小调整**：移动端字体放大，确保阅读舒适
3. **按钮加大**：Checklist勾选框和按钮加大，便于触摸
4. **表格改为卡片**：材料清单等表格在移动端改为卡片式布局
5. **文件下载优化**：移动端下载文件自动保存到本地或提示分享

### 3.4 无障碍设计考虑

- 所有交互元素支持键盘导航
- 图片提供alt文本描述
- 颜色对比度符合WCAG 2.1 AA标准
- 表单输入提供明确的label和错误提示

### 4.3 内容更新流程

**更新场景及操作：**

1. **修改某个步骤的内容**
   - 直接编辑对应的Markdown文件
   - 无需修改代码，网页自动读取最新内容

2. **添加新的国家**
   - 复制一套步骤文件（01-10），放在新文件夹
   - 修改配置文件`content-config.json`，添加新国家信息

3. **更新模板文件**
   - 直接替换`/templates`目录下的文件
   - 如有文件名变化，需同步更新Markdown中的下载链接

## 五、非功能性需求

### 5.1 性能要求

- 首屏加载时间 < 2秒
- 步骤页面切换响应时间 < 500ms
- 支持离线阅读（PWA模式，可选）
- 文件下载速度 > 500KB/s

### 5.2 浏览器兼容性

**必须支持：**
- Chrome 90+
- Safari 14+
- Firefox 88+
- Edge 90+

**移动端：**
- iOS Safari 14+
- Android Chrome 90+
- 微信内置浏览器

### 5.3 数据安全与隐私

- 用户进度数据仅存储在本地浏览器（localStorage）
- 不收集用户个人敏感信息
- 激活码验证不上传用户数据到服务器
- 提供"清除所有数据"功能，用户可随时删除本地记录

### 5.4 SEO优化考虑

- 所有页面支持服务端渲染（SSR）或静态生成（SSG）
- 合理的URL结构：如 `/italy/step01`
- Meta标签优化：标题、描述、关键词
- 结构化数据标记（Schema.org）
- sitemap.xml 生成
