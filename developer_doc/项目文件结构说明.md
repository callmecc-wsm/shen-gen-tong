## 📄 文件说明

### 根目录文件

#### README.md
- **作用**：项目首页，提供整体介绍和快速导航
- **内容**：
  - 项目简介和核心价值
  - 10步指南的目录导航
  - 快速开始指南
  - 官方联系方式
  - 免责声明

---

### docs/ 目录

存放所有产品需求文档（PRD）和用户指南。

#### PRD_主文档.md
- **作用**：产品需求的总纲文档
- **内容**：
  - 项目概述、背景、痛点分析
  - 产品定位和目标用户
  - 功能架构设计
  - 各模块说明（激活码、国家选择、10步流程、Checklist等）
  - 页面交互与用户体验设计
  - 内容管理方案
  - 非功能性需求
  - 后续迭代规划

---

#### 10个步骤文档（01-10）

每个步骤文档遵循统一的结构：

**标准章节：**
1. **为什么这一步很重要**：说明步骤的意义
2. **核心内容**：详细的操作指南和要求
3. **常见错误提示**：用红色高亮的注意事项
4. **情绪缓解话术**：减少用户焦虑的温暖文字
5. **工具和模板**：可下载的资源链接
6. **Checklist**：本步骤的待办事项清单
7. **下一步导航**：引导到下一个步骤

**具体文件说明：**

| 文件 | 核心内容 |
|------|---------|
| `01_领区确认.md` | 如何判断是否属于重庆领区，户籍和居住证要求 |
| `02_主目的地判断.md` | 主目的地原则详解，停留天数计算方法 |
| `03_时间规划与预约.md` | 申请时间窗口、VFS预约流程、时间规划表 |
| `04_材料清单总览.md` | 所有必须材料的详细要求和准备指南 |
| `05_行程与预订.md` | 机票酒店预订技巧，行程单编制指南 |
| `06_财力与在职证明.md` | 银行流水、在职证明、特殊人群材料 |
| `07_细节检查.md` | 表格签名、照片规格、翻译公证、材料装订 |
| `08_递交流程.md` | 签证中心现场流程Step by Step |
| `09_费用说明.md` | 费用构成、支付方式、增值服务 |
| `10_审理与取证.md` | 进度查询、电调应对、领取护照、入境提示 |

## 📝 内容维护指南

### 更新单个步骤

1. 直接编辑对应的步骤文档（如`03_时间规划与预约.md`）
2. 无需修改其他文件
3. 如有重大变动，同步更新`PRD_主文档.md`中的相关章节

---

### 添加新国家

**步骤：**
1. 复制`docs/`目录下的所有步骤文档（01-10）
2. 放入新文件夹（如`docs/france/`）
3. 修改每个文件的具体内容（适配新国家要求）
4. 更新`config/content-config.json`，添加新国家信息
5. 在`README.md`中添加新国家的导航入口

---

### 添加新模板

1. 将模板文件放入`templates/`目录
2. 在`附录_材料模板说明.md`中添加该模板的使用说明
3. 在对应的步骤文档中添加下载链接

---

### 更新FAQ

直接编辑`附录_常见问题FAQ.md`，按照已有格式添加新问题。

## 🎨 文档风格指南

### Markdown格式规范

**标题层级：**
- `#` 一级标题：文档标题（仅一个）
- `##` 二级标题：主要章节
- `###` 三级标题：子章节
- `####` 四级标题：细节点

**强调样式：**
- **粗体**：关键术语、重要信息
- *斜体*：轻微强调或英文术语
- `代码样式`：文件名、专有名词、技术术语

**列表：**
- 无序列表：用`-`或`•`
- 有序列表：用数字`1. 2. 3.`
- Checklist：用`- [ ]`（未完成）和`- [x]`（已完成）

**表格：**
- 用于结构化信息展示
- 第一行为表头
- 使用`|`和`-`绘制

**引用和提示框：**
- `> 引用内容`：用于引用或说明
- `⚠️`、`❌`、`✅`、`💡`等emoji：快速识别信息类型

---

### 信息层级设计

**🔴 严重错误/强制要求**
- 红色背景或`<span style="color:red;">`标记
- 用于必须遵守的硬性规定

**⚠️ 重要提示/常见错误**
- 黄色emoji或边框
- 用于容易踩坑的地方

**💡 贴心提示/优化建议**
- 蓝色emoji
- 用于增值建议和小技巧

**💚 情绪缓解/鼓励话术**
- 绿色emoji
- 用于缓解用户焦虑

---

### 语言风格

**语气：**
- 亲切、专业、鼓励
- 使用第二人称"您"
- 避免官腔和生硬用语

**解释方式：**
- 复杂概念用比喻或示例
- 提供具体场景而非抽象描述
- 正确示例 vs 错误示例对比

**长度控制：**
- 每个步骤文档：3000-5000字为宜
- 段落不要过长，保持可读性
- 善用小标题拆分内容

## 🔄 版本控制

### Git提交规范

**提交信息格式：**
```
<type>: <description>

类型（type）：
- feat: 新增功能或步骤
- fix: 修复错误
- docs: 文档更新
- style: 格式调整（不影响内容）
- refactor: 重构（不改变功能）
- chore: 其他杂项
```

**示例：**
```
feat: 添加步骤06财力证明详解
fix: 修正步骤03中VFS预约链接
docs: 更新FAQ中关于电调的问题
```

---

### 文档版本号

**格式：** vX.Y（如v1.0、v1.1）

**X（主版本号）：**
- 重大功能变更
- 新增国家

**Y（次版本号）：**
- 内容更新和优化
- 新增FAQ或模板
- 修复错误
